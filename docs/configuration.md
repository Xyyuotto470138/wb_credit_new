# Team configuration contract

`load_team(team_id)` reads seven safe YAML files under `config/teams/<team_id>/`. It validates unknown fields, IDs/references, rule shapes, dependency cycles, alternative groups, formula operators and workflow roles/outcomes. It rejects path traversal. A canonical SHA-256 hash covers all seven parsed files. Case storage pins the full validated snapshot plus version/hash; drafts and ES versions pin the case hash.

- `template.yaml`: 14 exact FIG section names, descriptions, input maps and draft-mode labels; section applicability/mandatory predicates and CA safeguards; owner template path and mapping conventions. Full observed anchor mappings belong to B22.
- `catalogue.yaml`: 22 exact project rows plus executable predicates, owner groups, public-support scope and generation/confirmation flags. Annual report/financial statement are one alternative group. Conditional inputs become mandatory when their applicability rule matches. Prior ES/prior conditions apply to existing clients but are mandatory only for renewal. Section 3 is mandatory for renewal, optional for new cases. Conduct applies only to existing clients.
- `rules.yaml`: alternatives, case/document-triggered suggestions, draft gates and public/generated evidence safeguards. Suggestions remain Suggested. B05 evaluates expected lists and readiness; see `docs/readiness.md` for the evidence and generation contracts.
- `dependencies.yaml`: 9 needs 7/10; 11 needs applicable 3–10; 14 needs all mandatory applicable sections plus CA position.
- `analytics.yaml`: ten REIT measures, operand/formula vocabulary, units, missing-value policy and source/effective date for project-stated thresholds. The regulatory definitions remain **pending B10 verification**. This file performs no arithmetic and makes no new regulatory claim. Bank analytics are not invented.
- `prompts.yaml`: section guidance, citations/gaps/synthetic labels, supplied rating and CA-owned conclusion.
- `workflow.yaml`: CA, Credit Head, Credit Approver and template admin; support separate from handoff; five approver outcomes; conditions enabled by default; final outcomes locked; question answers return directly to approver. Optional credit admin support is disabled pending S06.

Predicates use `always`, `eq`, `in`, `contains`, `all`, `any`, `not` over declared case attributes. No YAML expression is evaluated as code. `new` and `renewal` are case types; `existing_client` and `new_to_bank` explicitly distinguish a new facility for an existing client. Security, covenants, facility types and repayment flags are supplied case facts, not assumptions made from missing documents. Term/acquisition facility types or new money trigger projections. Fund borrowers or a deal with an information memorandum trigger that document type.

Public report/statements/ownership/fund evidence can close required inputs only after confirmation. Full valuation/lease reports are client requests; annual-report summaries are partial evidence. Rating catalogue item 10 requires internal rating; external releases are separate suggestions. Item 19 can generate an industry-code suggestion but requires CA confirmation. The rule evaluator alone does not close a gap.

A test-only alternate team loads from copied configuration with a different ID/title/version and the conditions outcome disabled. Core code has no FIG-specific section/count branches. New teams must use the supported predicate/formula vocabulary; new operators require code/review. This test is not a business template for CBK/CMB.

The provider is injected using `Provider` (`chat`, `chat_raw`, `get_provider_info`). `create_provider()` defaults to mock-v1; it reads neither `.env` nor process credentials. JSON fixtures map a canonical request hash (messages/token limit/temperature/timeout) to `{text, stop_reason, content}`. Missing or malformed fixtures fail explicitly; there is no live fallback. Usage records provider/model/config/fixture versions, request hash and zero cost, without message contents or secrets. Live provider selection deliberately raises until an approved paid-run task implements the adapter and spend ceiling. No live model is chosen in advance.

B06 adds optional `public_search: true` to eligible suggestion rules. It defaults to false and preserves older case pins; catalogue eligibility still follows `public_support`. See [public search](public_search.md) for the identity-only query and confirmation contracts.
